# FinDecode

금융 지식이 부족한 비전공자를 위한 **금융 리포트 이해 보조 어시스턴트**입니다.
증권사 리포트·펀드 설명서·경제 전망 보고서 등 어려운 금융 문서를 붙여넣거나 PDF로 올리면, 쉬운 말 요약·전문용어 설명·인사이트 3가지를 뽑아 보여줍니다.

## 무엇을 하는 앱인가

| 기능 | 설명 |
|---|---|
| 쉬운 요약 | 원문의 핵심 결론·수치를 놓치지 않는 평이한 문장 요약 |
| 키워드 설명 | PER, 콜옵션, 듀레이션 같은 전문용어를 감지해 쉬운 설명 + 원문 근거 문장과 함께 제공 |
| 인사이트 | 원문에 근거한 시사점을 기회/리스크/참고로 분류해 제시 |
| 히스토리 | 과거 분석 결과를 다시 열람 |

투자 자문(매수/매도 추천)이나 사실 검증(팩트체크)은 범위 밖입니다 — 자세한 내용은 [PRD.md](PRD.md) 참고.

## 기술 스택 / 아키텍처

프론트엔드는 빌드 도구나 프레임워크 없이 **순수 HTML/CSS/JS 3파일**(`index.html`, `style.css`, `app.js`)로 구성됩니다. 백엔드는 별도 서버 없이 **Supabase**만 사용합니다.

```
브라우저 (index.html/app.js)
   │
   ├─ PDF 업로드 시: pdf.js(CDN)로 브라우저에서 텍스트만 추출
   │
   ├─ 분석 요청 → Supabase Edge Function "analyze-report"
   │                  └─ 서버 측 시크릿(ANTHROPIC_API_KEY)으로 Claude API 호출
   │                     (Anthropic 키는 브라우저에 절대 내려오지 않음)
   │
   └─ 분석 결과 저장 → Supabase Postgres (analyses / analysis_keywords / analysis_insights, RLS 적용)
                     └─ 동시에 localStorage에도 캐시 (오프라인 히스토리 열람용)
```

이렇게 나눈 이유:
- **API 키를 브라우저에 두지 않기 위해**: 프론트엔드가 Claude를 직접 호출하면 개발자도구/네트워크 탭으로 누구나 API 키를 볼 수 있습니다. Edge Function을 한 단계 두면 키는 서버 측 시크릿으로만 존재합니다.
- **분석 결과를 기기/브라우저를 넘어 보존하기 위해**: `localStorage`만 쓰면 다른 브라우저·기기에서는 히스토리가 보이지 않습니다. Supabase DB에도 적재해 두면 나중에 로그인 기능을 붙였을 때 기기 간 동기화로 자연스럽게 확장할 수 있습니다.
- **그럼에도 프레임워크(React 등)는 도입하지 않음**: 화면이 4개 미만인 폼 기반 도구라 프레임워크가 주는 이점(컴포넌트 재사용, 상태관리)이 거의 없고, 빌드 단계가 생기면 오히려 `file://`로 바로 열어보는 지금의 단순함을 잃습니다.

## 실행 방법

빌드 과정이 없습니다. `index.html`을 더블클릭해서 열거나, 정적 파일 서버로 서빙하면 됩니다.

```bash
# 예: 로컬 정적 서버로 열기
npx serve .
```

Claude API 키는 사용자가 입력할 필요가 없습니다 — Supabase Edge Function의 서버 측 시크릿(`ANTHROPIC_API_KEY`)으로 관리됩니다.

## Supabase 스키마

프로젝트: `samsung_ai` (`wdciuciczkhirihersei`)

| 테이블 | 역할 |
|---|---|
| `analyses` | 분석 1건 (원문, 요약, 사용 모델, 소요시간 등) |
| `analysis_keywords` | 분석에 딸린 키워드 설명 (1:N) |
| `analysis_insights` | 분석에 딸린 인사이트 (1:N) |

세 테이블 모두 RLS(Row Level Security)가 켜져 있습니다. 로그인 기능이 아직 없어 `user_id`는 항상 NULL로 저장되며, 현재 정책은 `user_id is null`인 행에 한해 anon 키로 CRUD를 허용합니다 — 즉 **로그인 전까지는 익명 사용자끼리 서로의 분석 데이터를 볼 수 있는 상태**입니다. 민감한 문서를 다룬다면 로그인 기능을 먼저 추가해야 합니다.

## 알려진 한계

- 근거성(hallucination) 검증 없음: 모델이 원문에 없는 내용을 인용문으로 제시해도 그대로 표시됩니다.
- 위에서 설명한 대로 익명 사용자 간 데이터 격리가 없습니다.
- 히스토리 삭제, 요청 재시도(429/529), 분석 중 입력창 잠금 등은 아직 없습니다.
